# LeafEvents

Плагин ивентов с лутом для Paper 1.21 и Java 21. Пакет: `com.agent1k`.
PlaceholderAPI 2.11.6 поддерживается как необязательная зависимость.

## Команды

Для всех команд и редакторов необходимо право `leafevents.admin`, по умолчанию доступное операторам.

- `/leafevents` — помощь.
- `/leafevents create <id> <название>` — создать ивент. Название может содержать пробелы, `&` и `&#RRGGBB`.
- `/leafevents menu` — список ивентов с переключением страниц.
- `/leafevents start <id>` — запустить ивент.
- `/leafevents stop <id>` — остановить ивент.

Автодополнение предлагает подкоманды и идентификаторы для `start` и `stop`.
Консоль может создавать, запускать и останавливать ивенты; меню доступны игрокам.

## Редакторы

В списке ивентов ЛКМ открывает редактор лута, ПКМ — редактор шансов.
В редактор лута можно класть предметы и убирать их; изменения сохраняются при закрытии.
Предметы сериализуются средствами Bukkit с метаданными. Новые предметы получают шанс 100%.
Для прежнего предмета в прежнем слоте сохраняется установленный шанс.
Редактировать один ивент одновременно может только один игрок.

Редактор шансов использует управление как в BAirDrop:

- ЛКМ: −1%.
- ПКМ: +1%.
- Shift+ЛКМ: −10%.
- Shift+ПКМ: +10%.

Значения ограничены диапазоном 0–100%. Изменение сохраняется сразу.
Лор редактора добавляется только к отображаемым копиям предметов.
Меню защищено от извлечения предметов, shift-переноса, цифровых клавиш и перетаскивания.
При большом количестве предметов доступны страницы.
Каждый слот лута разыгрывается независимо при старте ивента: 0% никогда, 100% всегда.
Лут запущенного ивента отделён от шаблона, поэтому его редактирование влияет на последующие запуски.

## Конфигурация

При первом запуске создаются `messages.yml`, `menus/menu.yml`, `menus/event-chance.yml` и папка `events`.
Команда `create` создаёт `events/<id>.yml`. Настройки читаются в память при включении плагина.
Для применения ручных изменений YAML нужен штатный перезапуск сервера.
Не редактируйте YAML одновременно с открытым редактором: сохранение редактора записывает настройки из памяти.

Пример конфигурации созданного ивента:

```yaml
airdrop-settings:
  material: CHEST
  random-spawn: true
  event-world: [world]
  location-spawn:
    enabled: false
    coordination:
      x: 0
      y: 0
      z: 0
  spawn-time: 500
  stop-time: 1500
  unlock-time: 60
  online: 1
  spawn-radius: 1000
inventory-settings:
  name: '&fТестовый аир'
  size: 54
  inventory-loot: {}
```

`spawn-time` — интервал автоматической попытки запуска в секундах, отсчитываемый после остановки.
`stop-time` — полная длительность ивента в секундах с момента появления, включая блокировку. `unlock-time` — время блокировки лута с момента появления; `0` отключает её. Значение должно быть меньше `stop-time`. Новые ивенты получают блокировку на 60 секунд. Для старых YAML без этого поля используется 60 секунд, но не больше `stop-time − 1`. `online` проверяется и при ручном запуске.
При недостаточном онлайне или отсутствии безопасного места автоматическая попытка повторяется через `spawn-time`.
`inventory-settings.size` — число слотов, кратное 9, от 9 до 54. Нумерация слотов начинается с нуля.
Лут сохраняется как `inventory-settings.inventory-loot.<slot>.item` и `.chance`.

При `location-spawn.enabled: true` используются заданные координаты в одном из разрешённых загруженных миров.
Иначе `random-spawn: true` выбирает безопасную поверхность в радиусе `spawn-radius` от центра границы мира.
Поиск ограничен 64 попытками. Место должно находиться в границе мира, над твёрдым блоком, с двумя свободными блоками воздуха.
При `random-spawn: false` ручной запуск размещает ивент у ног игрока в разрешённом мире; автоматический запуск в этом режиме отключён, если не заданы фиксированные координаты.
Для мира с несколькими разрешёнными именами выбирается случайный загруженный мир.

До истечения `unlock-time` открыть лут нельзя. При ПКМ игрок видит оставшееся время, округлённое вверх до целой секунды. По окончании таймера игрокам отправляется сообщение `event-unlocked`; при нулевом таймере ивент доступен сразу без отдельного сообщения об открытии. Административные редакторы шаблона лута и шансов остаются доступны независимо от таймера.

Ивент открывается ПКМ по его блоку. Инвентарь общий для всех игроков.
На время работы чанк удерживается загруженным; блок защищён от разрушения, взрывов, огня и поршней.
При остановке или штатном отключении плагина открытые инвентари закрываются, остатки лута удаляются, исходный блок восстанавливается.
Принудительное завершение процесса сервера не вызывает обработчик отключения.

## Тестовый ивент

При первом включении версии с примерами создаётся `events/test.yml`:

- ID: `test`, название: «Тестовый аирдроп».
- Мир: `world`, случайная безопасная поверхность в радиусе 1000 блоков.
- Блокировка: 30 секунд, полная длительность: 300 секунд.
- Минимальный онлайн: 1, автоматическая попытка запуска через 500 секунд.
- Лут: 3 алмаза (100%), 2 золотых яблока (50%), 16 железных слитков (100%).

Ручной запуск: `/leafevents start test`. Содержимое и шансы меняются через `/leafevents menu`.

Файл можно изменять, удалить или переименовать, например в `my-air.yml`: после перезапуска его ID будет `my-air`. Имя файла должно соответствовать тем же правилам, что ID команды `create`. Удалять и переименовывать файлы следует при выключенном сервере, чтобы открытый редактор не записал старое имя заново.

Служебный файл `.example-event-installed` в папке плагина запоминает первоначальную установку примера. Пока он существует, удалённый или переименованный `test.yml` не восстанавливается. Существующий `events/test.yml` не перезаписывается. Для намеренного повторного создания примера удалите маркер и запустите сервер заново. Это самостоятельный пример для формата LeafEvents, а не YAML от BAirDrop.

## Действия меню и сообщений

- `[message] <текст>` — отправить сообщение.
- `[open-inventory]` — открыть редактор лута выбранного ивента.
- `[open-menu] <имя>` — открыть меню из папки `menus` по имени YAML без расширения.
- `[chance] <изменение>` — изменить шанс выбранного предмета в редакторе шансов.
- `[page] <изменение>` — сменить страницу текущего меню.
- `[close]` — закрыть меню.

Ключи действий: `left_click_action`, `right_click_action`, `shift_left_click_action`, `shift_right_click_action`.
Для совместимости с примерами ТЗ поддерживаются также `left-action_click`, `left_action_click`, `right_action_click`, `right-action_click`.
Пустые строки сообщений отправляют пустую строку в чат.
В `menu-settings.events.slot` задаются неповторяющиеся слоты карточек.
Кнопки в `items` имеют `material`, `name`, `lore`, `slot` и действия; их слоты должны быть вне слотов карточек.
Тип меню `events` отображает ивенты, тип `chance` — предметы выбранного ивента.

## Плейсхолдеры

Интеграция устроена как в GlowClans: `PapiApi` напрямую наследуется от `PlaceholderExpansion`, регистрируется в `onEnable`, а сообщения и меню обрабатываются через `PlaceholderAPI.setPlaceholders`. Вложенного расширения, отдельного `TextService` и кеша последнего выбранного ивента нет. Для подстановки нужен установленный PlaceholderAPI; без него плагин работает, но текстовые плейсхолдеры остаются без подстановки. Старый параметр `placeholder-context-ttl-seconds` больше не используется, создавать `config.yml` для него не требуется.

| Плейсхолдер | Значение |
| --- | --- |
| `%leafevents_event_name%` | Название ивента |
| `%leafevents_event_id%` | ID ивента |
| `%leafevents_coordination%` | Координаты `X Y Z` |
| `%leafevents_world%` | Название мира |
| `%leafevents_state%` | `запущен` или `остановлен` |
| `%leafevents_unlock_seconds%` | Секунды до открытия лута, с округлением вверх |
| `%leafevents_unlock_state%` | `заблокирован` или `доступен` |
| `%leafevents_event_label%` | Пример пользовательского плейсхолдера из `messages.yml` |

В меню и сообщениях короткая форма относится к ивенту текущей операции. Для внешнего запроса, например из TAB или голограммы, указывайте ID в конце параметра: `%leafevents_event_name_test%`, `%leafevents_unlock_seconds_test%`, `%leafevents_state_test%`. Так доступны все встроенные значения и пользовательские плейсхолдеры. ID с подчёркиванием и дефисом поддерживаются: `%leafevents_event_name_my_air-1%`.

Без ID и без текущей операции используется первый запущенный ивент по алфавиту ID. Если активных ивентов нет, название, ID, координаты, мир и состояние блокировки пустые; время до открытия равно `0`, состояние — `остановлен`. Явный ID позволяет получить название и состояние остановленного ивента; координаты и мир доступны только после запуска.

Пользовательские текстовые плейсхолдеры задаются в секции `placeholders` файла `messages.yml`, например `event_label: '&fИвент: %leafevents_event_name%'`. Вложенные значения обрабатываются через PlaceholderAPI, включая плейсхолдеры других плагинов. Циклические ссылки и вложенность более восьми пользовательских подстановок обрываются пустой строкой. Встроенные имена имеют приоритет над пользовательскими.

Контекст текущей операции очищается сразу после обработки текста, в том числе при исключении. Он изолирован по потоку и не сохраняет выбор игрока между командами.

## Проверка исходников

Сборка плагина и запуск сервера не выполнялись по просьбе заказчика. Логика таймера и однократной установки примера дополнительно проверяется изолированно от Paper.
Проведён синтаксический разбор Java без компиляции проекта и проверка формата YAML/XML. Прямое расширение PAPI проверено в 30 изолированных сценариях с имитацией платформы, включая явные ID, циклические шаблоны, очистку контекста при исключениях и параллельные операции. Проверка с настоящим PlaceholderAPI на Paper не выполнялась.
Совместимость с API и поведение на сервере требуют отдельной сборки и проверки.
Механика редактора изучена по открытому репозиторию https://github.com/By1337/BAirDrop, реализация LeafEvents написана самостоятельно.
